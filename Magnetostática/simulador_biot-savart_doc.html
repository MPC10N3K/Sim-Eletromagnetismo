1. Visão geral

O simulador resolve numericamente o seguinte problema: dada uma curva fechada ou aberta percorrida por uma corrente elétrica \(I\), desenhar as linhas de campo magnético \(\mathbf{B}\) que ela produz no espaço.

Para isso, quatro etapas se sucedem:

Etapa 1 Discretizar a curva do fio em pequenos segmentos e calcular, para cada segmento, a contribuição ao campo via lei de Biot–Savart. Cada segmento carrega a corrente local \(I(t)\) no parâmetro \(t\) daquele trecho.
Etapa 2 Escolher sementes: pontos no espaço de onde as linhas de campo vão partir.
Etapa 3 Integrar a equação diferencial \(\frac{d\mathbf{r}}{ds} = \frac{\mathbf{B}(\mathbf{r})}{\|\mathbf{B}(\mathbf{r})\|}\) a partir de cada semente, produzindo uma polilinha que é a linha de campo.
Etapa 4 Colorir cada ponto da linha pelo valor local \(\|\mathbf{B}\|\), eventualmente transformado por uma escala (linear ou logarítmica).

2. O campo magnético: lei de Biot–Savart

A lei de Biot–Savart dá o campo magnético produzido por um elemento infinitesimal de fio \(d\boldsymbol{\ell}\) percorrido por corrente \(I\), num ponto \(\mathbf{r}\):

$$d\mathbf{B}(\mathbf{r}) = \frac{\mu_0 I}{4\pi}\,\frac{d\boldsymbol{\ell} \times (\mathbf{r} - \mathbf{r}')}{\|\mathbf{r} - \mathbf{r}'\|^{3}}$$

onde \(\mathbf{r}'\) é a posição do elemento de fio, e \(\mathbf{r}\) é o ponto onde se mede o campo. O campo total é a integral ao longo de toda a curva \(\mathcal{C}\):

$$\mathbf{B}(\mathbf{r}) = \frac{\mu_0}{4\pi}\oint_{\mathcal{C}} I(\mathbf{r}') \, \frac{d\boldsymbol{\ell} \times (\mathbf{r} - \mathbf{r}')}{\|\mathbf{r} - \mathbf{r}'\|^{3}}$$

A corrente \(I\) foi escrita dentro da integral porque o simulador permite corrente variável ao longo do fio (detalhes na seção 4).

Constantes e unidades

O simulador trabalha em unidades arbitrárias: assume \(\mu_0/(4\pi) = 1\). Isso não afeta a geometria das linhas de campo (que só depende da direção de \(\mathbf{B}\)), apenas a escala dos valores de \(\|\mathbf{B}\|\) mostrados na barra de cores. A constante \(1/(4\pi)\) aparece explicitamente no código:

const c = 1/(4*Math.PI);
out[0] = bx*c; out[1] = by*c; out[2] = bz*c;
Por que a direção basta? As linhas de campo são as curvas tangentes a \(\mathbf{B}\) em cada ponto. Multiplicar \(\mathbf{B}\) por uma constante positiva não muda as tangentes — só o parâmetro de comprimento de arco. Por isso a integração normaliza \(\mathbf{B}\) a cada passo.

3. Discretização da curva

Uma curva contínua é aproximada por \(N\) pontos amostrados em \(t \in [t_{\min}, t_{\max}]\):

$$\mathbf{r}_i = \bigl(x(t_i),\, y(t_i),\, z(t_i)\bigr), \qquad t_i = t_{\min} + (t_{\max} - t_{\min})\,\frac{i}{N-1}, \quad i = 0, \ldots, N-1$$

A curva fica dividida em \(N_s = N - 1\) segmentos. Para cada segmento \(i\), o programa guarda:

SímboloDefiniçãoSignificado
\(\mathbf{m}_i\) \(\dfrac{\mathbf{r}_{i+1} + \mathbf{r}_i}{2}\) Ponto médio do segmento
\(d\boldsymbol{\ell}_i\) \(I(t_i) \, (\mathbf{r}_{i+1} - \mathbf{r}_i)\) Vetor do segmento já multiplicado pela corrente local

A integral de Biot–Savart vira então uma soma sobre os segmentos:

$$\mathbf{B}(\mathbf{r}) \approx \frac{1}{4\pi}\sum_{i=0}^{N_s-1} \frac{d\boldsymbol{\ell}_i \times (\mathbf{r} - \mathbf{m}_i)} {\bigl(\|\mathbf{r} - \mathbf{m}_i\|^{2} + \varepsilon\bigr)^{3/2}}$$

onde \(\varepsilon = 10^{-8}\) é uma regularização que evita divisão por zero quando \(\mathbf{r}\) coincide com um segmento. Sem ela, o campo divergiria numericamente (embora fisicamente um fio ideal tenha campo infinito apenas sobre ele mesmo).

Implementação (o hot path do programa)

A função B(x,y,z,out) percorre todos os segmentos e acumula as contribuições. Foi otimizada para não alocar memória a cada chamada:

function B(x, y, z, out) {
  let bx = 0, by = 0, bz = 0, m = 1e30;
  for (let i = 0; i < NS; i++) {
    const j = 3*i;
    const rx = x - ML[j], ry = y - ML[j+1], rz = z - ML[j+2];  // r - m_i
    const r2 = rx*rx + ry*ry + rz*rz;
    if (r2 < m) m = r2;                    // guarda a menor distância (p/ minD)
    const d = r2 + EPS, f = 1/(d*Math.sqrt(d));  // 1/(|r-m|^2 + eps)^(3/2)
    const lx = DL[j], ly = DL[j+1], lz = DL[j+2];   // dl_i (já com I(t_i))
    bx += (ly*rz - lz*ry) * f;             // (dl × r)_x / |r|^3
    by += (lz*rx - lx*rz) * f;
    bz += (lx*ry - ly*rx) * f;
  }
  minD2 = m;
  const c = 1/(4*Math.PI);
  out[0] = bx*c; out[1] = by*c; out[2] = bz*c;
}

A estrutura de dados é planar: ML e DL são Float64Array de comprimento \(3N_s\), guardando \((m_x, m_y, m_z, m_x', m_y', m_z', \ldots)\) contiguamente. Isso melhora a localidade de cache e evita a criação de \(N_s\) objetos.

Custo: cada chamada a B custa \(O(N_s)\). Como o integrador RK4 chama B quatro vezes por passo, e há \(S\) passos por linha e \(L\) linhas, o custo total é \(O(N_s \cdot S \cdot 4L)\). Para \(N_s = 3200\), \(S = 800\), \(L = 100\), são \(\approx 10^9\) operações — por isso o programa usa Web Worker para não bloquear a UI.

Por que ponto médio?

A fórmula usa \(\mathbf{m}_i\) (ponto médio) em vez de \(\mathbf{r}_i\) (ponto inicial) porque o erro de aproximação fica simétrico em relação ao segmento. É uma regra do ponto médio, com erro \(O(\Delta t^2)\) em vez de \(O(\Delta t)\) — para a mesma discretização, o campo calculado é mais preciso.

4. Corrente variável ao longo do fio

O campo de entrada I(t) é uma expressão do parâmetro \(t\) de cada segmento, e não do tempo global. Isso permite simular fios onde a corrente muda de ponto para ponto — por exemplo, uma antena de onda estacionária.

Para cada segmento \(i\), o programa avalia:

$$I_i = I\!\left(\frac{t_i + t_{i+1}}{2}\right)$$

e o vetor de segmento usado na soma já inclui essa corrente:

$$d\boldsymbol{\ell}_i = I_i \, (\mathbf{r}_{i+1} - \mathbf{r}_i)$$

Assim, o campo resultante é uma soma ponderada — segmentos com corrente forte contribuem mais; segmentos com corrente fraca (ou nula) contribuem pouco; segmentos com corrente negativa invertem o sentido local.

Casos comuns

I(t)Interpretação
1Corrente uniforme (caso clássico de Biot–Savart).
sin(2*pi*m*t)Onda estacionária em um fio enrolado com \(m\) voltas.
1 + 0.5*sin(2*pi*t)Modulação suave ao longo do fio.
No modo multi-fio, a corrente é atribuída por fração de arco dentro de cada fio: o primeiro fio usa \(I(0)\ldots I(1)\), o segundo também, e assim por diante. Isso preserva a interpretação de que \(I\) é função do parâmetro local de cada fio, não do índice do fio.

O fio pode ser colorido pela magnitude \(|I_i|\) usando o mesmo colormap do campo (checkbox "Colorir fio pela intensidade de I"). A normalização usa \(I_{\max} = \max |I_i|\), calculado diretamente dos valores efetivamente atribuídos aos pontos do fio.

5. Sementes: pontos de partida das linhas

As sementes são os pontos \(\mathbf{r}_0^{(1)}, \ldots, \mathbf{r}_0^{(L)}\) de onde cada linha de campo começa. A escolha determina quais linhas você verá — não é única, e diferentes distribuições revelam aspectos diferentes do campo.

O programa oferece quatro tipos:

5.1 Polar (anéis)

Sementes em anéis concêntricos. Dados \(r_{\min}, r_{\max}, z_{\min}, z_{\max}\), o número de raios \(n_r\), o número de níveis em \(z\), \(n_z\), e o número de pontos por anel \(n\):

$$r_a = r_{\min} + \frac{a}{n_r - 1}(r_{\max} - r_{\min}), \quad a = 0, \ldots, n_r - 1$$ $$z_b = z_{\min} + \frac{b}{n_z - 1}(z_{\max} - z_{\min}), \quad b = 0, \ldots, n_z - 1$$ $$\theta_c = \frac{2\pi c}{n}, \quad c = 0, \ldots, n - 1$$ $$\mathbf{r}_{abc} = \bigl(r_a\cos\theta_c,\; r_a\sin\theta_c,\; z_b\bigr)$$

Total: \(n_r \cdot n_z \cdot n\) sementes. Quando \(n_r = 1\) (ou \(n_z = 1\)), o programa coloca a coordenada no meio do intervalo, não no extremo:

const ls = (a, b, k) => k === 1 ? [(a+b)/2] : Array.from({length: k}, (_, i) => a + (b-a)*i/(k-1));
Essa escolha é importante para o preset padrão: um único raio em \(r_{\min}\) (quase sobre o fio) geraria linhas degeneradas, enquanto no meio do intervalo a linha é representativa.

5.2 Aleatória

Distribuição uniforme em raio e ângulo, dentro de um cilindro:

$$r = 0.2 + \xi_1\,(R_{\max} - 0.2), \quad \theta = 2\pi\xi_2, \quad z = z_{\min} + \xi_3\,(z_{\max} - z_{\min})$$

onde \(\xi_1, \xi_2, \xi_3 \in [0,1]\) são números pseudoaleatórios determinísticos (gerador mulberry32 com semente fixa). A semente fixa garante reprodutibilidade: a mesma configuração sempre produz a mesma imagem.

5.3 Linha

Sementes igualmente espaçadas sobre um segmento \(\mathbf{r}_A \to \mathbf{r}_B\):

$$\mathbf{r}_j = \mathbf{r}_A + \frac{j}{n-1}(\mathbf{r}_B - \mathbf{r}_A), \quad j = 0, \ldots, n-1$$

5.4 Grade no plano

Grade \(n \times n\) em \(z = z_0\) fixo:

$$\mathbf{r}_{ij} = \left(x_{\min} + \frac{i}{n-1}(x_{\max} - x_{\min}),\; y_{\min} + \frac{j}{n-1}(y_{\max} - y_{\min}),\; z_0\right)$$

Limite por perfil de performance

O número de sementes é limitado por um teto que depende do perfil escolhido:

PerfilTeto de sementes
Leve150
Padrão400
Avançado1000

Se a distribuição gerar mais sementes que o teto, o programa subamostra uniformemente (passo constante no array) em vez de simplesmente truncar no início — assim a distribuição espacial é preservada.

6. Integração das linhas de campo (RK4)

Uma linha de campo é a curva cuja tangente em cada ponto é paralela a \(\mathbf{B}(\mathbf{r})\). Parametrizando pelo comprimento de arco \(s\), isso é:

$$\frac{d\mathbf{r}}{ds} = \hat{\mathbf{B}}(\mathbf{r}) \equiv \frac{\mathbf{B}(\mathbf{r})}{\|\mathbf{B}(\mathbf{r})\|}$$

A normalização \(\hat{\mathbf{B}}\) garante que \(s\) avance a uma unidade de comprimento por passo, e não a um valor que depende de \(\|\mathbf{B}\|\).

6.1 Runge–Kutta de 4ª ordem

Para avançar de \(\mathbf{r}_n\) a \(\mathbf{r}_{n+1}\) com passo \(h\):

$$\begin{aligned} \mathbf{k}_1 &= \hat{\mathbf{B}}(\mathbf{r}_n) \\ \mathbf{k}_2 &= \hat{\mathbf{B}}\!\left(\mathbf{r}_n + \tfrac{h}{2}\mathbf{k}_1\right) \\ \mathbf{k}_3 &= \hat{\mathbf{B}}\!\left(\mathbf{r}_n + \tfrac{h}{2}\mathbf{k}_2\right) \\ \mathbf{k}_4 &= \hat{\mathbf{B}}\!\left(\mathbf{r}_n + h\,\mathbf{k}_3\right) \\ \mathbf{r}_{n+1} &= \mathbf{r}_n + \frac{h}{6}\bigl(\mathbf{k}_1 + 2\mathbf{k}_2 + 2\mathbf{k}_3 + \mathbf{k}_4\bigr) \end{aligned}$$

O erro local é \(O(h^5)\) e o global \(O(h^4)\) — com apenas 4 avaliações de \(\mathbf{B}\) por passo.

6.2 Passo adaptativo

O passo \(h_n\) se ajusta em três situações:

  1. Perto do fio (se o passo proposto cairia a menos de \(d_{\min}\) do fio): o passo é rejeitado e \(h\) é reduzido pela metade; o programa tenta de novo a partir do ponto anterior. Isso é o backtracking.
  2. Longe do fio (\(\min Dist^2 > 4\,d_{\min}^2\)) e ainda com passo pequeno: \(h\) cresce em 25%, até o limite \(h_{\text{user}}\).
  3. Variação brusca de \(\|\mathbf{B}\|\): \(h\) cresce se \(\|\mathbf{B}_{n+1}\|/\|\mathbf{B}_n\| > 2\) e \(h_n < 2h_{\text{user}}\); encolhe se a razão for menor que \(0.5\) e \(h_n > h_{\text{user}}/4\).
$$d_{\min} = \max\bigl(d_{\min}^{\text{user}},\; 0.3\,\overline{\Delta\ell}\bigr)$$

onde \(\overline{\Delta\ell}\) é o comprimento médio dos segmentos do fio. Isso evita que o RK4 pule por cima de um segmento em fios com poucos pontos.

6.3 Critérios de parada

Uma integração termina quando uma das condições ocorre:

CondiçãoRazão
Passos \(\geq S_{\max}\)Limite de passos do usuário
\(\|\mathbf{r}_{n+1}\| > R_{\max}\)Saiu da região de interesse
\(\|\mathbf{B}\| < 10^{-14}\)Ponto de equilíbrio (campo nulo)
\(\|\mathbf{r}_{n+1} - \mathbf{r}_0\| < 0.9h\) após \(n>8\)Linha fechou (voltou ao início)

O critério de fechamento é heurístico: se o ponto atual está a menos de um passo do ponto inicial, a linha é considerada fechada e completada com o próprio \(\mathbf{r}_0\) para que o plot feche visualmente.

6.4 Sentido de integração

O campo é um campo vetorial: em cada ponto há uma direção e um sentido. O simulador permite integrar:

  • Frente (\(\sigma = +1\)): segue \(\hat{\mathbf{B}}\);
  • Trás (\(\sigma = -1\)): segue \(-\hat{\mathbf{B}}\);
  • Ambas: integra nos dois sentidos e concatena as duas polilinhas.

Para integração bidirecional, a linha final é:

$$\{\mathbf{r}_{-K}, \ldots, \mathbf{r}_{-1}, \mathbf{r}_0, \mathbf{r}_{1}, \ldots, \mathbf{r}_{M}\}$$

onde o ramo negativo é revertido antes de concatenar, para que a curva fique na ordem geométrica correta.

7. Coloração e escalas

Cada ponto \(\mathbf{r}_n\) da linha tem um valor de \(\|\mathbf{B}(\mathbf{r}_n)\|\) associado (já incluindo a corrente local dos segmentos). Esse valor é usado para colorir a linha através de um colormap.

7.1 Normalização por percentil

Como \(\|\mathbf{B}\|\) varia por muitas ordens de grandeza, o programa clipa no percentil 95 dos valores:

$$\|\mathbf{B}\|_{\text{ref}} = \text{percentil}_{95}\bigl\{\|\mathbf{B}(\mathbf{r}_n)\|\bigr\}$$

e define o colormap sobre \([0, \|\mathbf{B}\|_{\text{ref}}]\). Valores acima aparecem na cor máxima. Isso evita que pontos muito próximos ao fio "queimem" toda a escala.

7.2 Escala linear ou logarítmica

O usuário pode escolher entre duas escalas de cor:

EscalaTransformação aplicada a \(\|\mathbf{B}\|\)
Linear\(\|\mathbf{B}\|\) direto.
Log(1+|B|)\(\log(1 + \|\mathbf{B}\|)\).

A escala \(\log(1+x)\) é particularmente útil porque:

  • Perto do fio, comporta-se como \(\log\|\mathbf{B}\|\), comprimindo a faixa alta e revelando gradientes onde a escala linear satura.
  • Longe do fio, comporta-se como \(\|\mathbf{B}\|\) (já que \(\log(1+x) \approx x\) para \(x \ll 1\)), preservando a leitura de magnitudes pequenas.
  • É suave em zero: \(\log(1+0) = 0\), sem o "penhasco" numérico que \(\log(x)\) produziria perto de pontos de campo nulo.

A colorbar exibe ticks em valores reais de \(\|\mathbf{B}\|\), espaçados geometricamente no domínio de \(\|\mathbf{B}\|\) (não no espaço transformado), com a posição visual correspondendo ao valor \(\log(1+\|\mathbf{B}\|)\). Assim o usuário lê o valor físico correto sem precisar desfazer a transformação mentalmente.

7.3 Troca de escala sem refazer a física

Como a geometria das linhas não depende da escala de cor, trocar de linear para logarítmica não recalcula a integração: apenas reescala as cores via Plotly.restyle:

function recolorOnly() {
  // Recalcula cmax, ticks, título da colorbar e cores.
  // Não toca em ML, DL, base.X, base.Y, base.Z.
}

O mesmo vale para a animação: como a geometria é fixa, o programa só reescala as cores a ~30 fps.

Observação: como \(I(t)\) pode ser negativa, o campo aponta no sentido oposto em alguns trechos. As linhas de campo como conjuntos continuam as mesmas, mas a orientação local inverte. A coloração usa \(\|\mathbf{B}\|\) (magnitude), então a cor não distingue sentido.

7.4 Fio colorido por \(I\)

O fio pode ser colorido pela magnitude \(|I_i|\) de cada ponto, usando o mesmo colormap. A normalização usa \(I_{\max} = \max |I_i|\), calculado diretamente dos valores atribuídos aos pontos do fio.

8. Geometrias multi-fio

Alguns presets (linhas paralelas, anéis paralelos, anéis concêntricos) geram múltiplos fios desconexos. Eles não são parametrizados por uma única expressão \(x(t), y(t), z(t)\) contínua — isso introduziria segmentos de salto espúrios na integral de Biot–Savart.

Em vez disso, a função buildMulti gera \(M\) curvas independentes:

$$\mathcal{C} = \mathcal{C}_1 \cup \mathcal{C}_2 \cup \cdots \cup \mathcal{C}_M$$

Como a integral de Biot–Savart é linear na curva, somar as contribuições dos \(M\) fios é exatamente o mesmo que integrar sobre \(\mathcal{C}\):

$$\mathbf{B}(\mathbf{r}) = \sum_{k=1}^{M} \mathbf{B}_{\mathcal{C}_k}(\mathbf{r})$$

Na renderização, o Plotly recebe as \(M\) polilinhas separadas por null (quebra visual), mas ML/DL contêm todos os segmentos contíguos para o cálculo do campo.

Convenções dos presets

PresetParâmetrosGeometria
Linhas paralelas \(M\), \(L\), \(a\) \(x_k = (k - \frac{M-1}{2})a\), \(y \in [-L/2, L/2]\), \(z = 0\)
Anéis paralelos \(M\), \(R\), \(a\) raio \(R\), \(z_k = (k - \frac{M-1}{2})a\), plano \(xy\)
Anéis concêntricos \(M\), \(R_0\), \(a\) raio \(R_k = R_0 + ka\), plano \(z=0\)

Em todos, \(M\) é forçado a inteiro maior ou igual a 1.

9.2 Preset Personalizado

O preset Personalizado permite escrever \(x(t), y(t), z(t)\) livremente. As variáveis detectadas viram sliders. O estado é salvo em localStorage e restaurado ao reabrir a página. Os presets originais não são alterados.

Ao selecionar Personalizado, o programa:

  1. Tenta carregar o estado salvo em localStorage.
  2. Se não houver estado salvo, copia o preset anterior (se não for multi-fio) como ponto de partida.
  3. Restaura expressões, parâmetros, tipo de semente e valores de semente.

Qualquer alteração em campos de expressão, parâmetros, sementes ou integração salva o estado automaticamente.

9.3 Detecção de parâmetros

As variáveis livres são detectadas via AST do math.js, ignorando:

  • constantes conhecidas (\(t, s, \pi, e, \tau, \ldots\));
  • funções nativas do math.js (para não criar sliders para \(\sin\), \(\cos\), etc.);
  • variáveis atribuídas nas "Definições auxiliares".

A filtragem é feita com:

if (x.isSymbolNode
    && !SKIP.has(x.name)
    && typeof math[x.name] !== 'function'
    && !as.has(x.name)) { /* é parâmetro */ }

10. Arquitetura e fluxo do programa

O programa é uma única página HTML com JavaScript inline. O fluxo de uma execução (run()) é:

1 Compilar as expressões \(x(t), y(t), z(t)\) e \(I(t)\) com math.js. As compilações são cacheadas por string (até 80 entradas).
2 Amostrar a curva em \(N\) pontos, calcular ML, DL e atribuir a corrente local \(I_i\) a cada segmento.
3 Gerar as sementes de acordo com a distribuição escolhida e o teto do perfil.
4 Integrar cada linha com RK4 + backtracking. Isso é feito em um Web Worker quando disponível, para não bloquear a UI.
5 Renderizar com Plotly.react, preservando a câmera 3D via uirevision e restauração explícita da câmera anterior.

Worker: por que existe

A integração é \(O(N_s \cdot S \cdot 4L)\). O Worker roda em thread separada, recebendo ML/DL como ArrayBuffer. Como o programa principal ainda precisa desses buffers para renderizar, ele envia cópias (slice(0)) — a transferência zero-copy não é usada aqui porque o mesmo buffer precisa ser lido depois pela thread principal.

const mlc = ML.buffer.slice(0);
const dlc = DL.buffer.slice(0);
w.postMessage({ ML: mlc, DL: dlc, NS, seeds, ... }, [mlc, dlc]);

Ao terminar, o Worker devolve {res, traced}, e o programa principal monta os traces do Plotly. O Worker é terminado e seu blob URL revogado imediatamente após o uso — evitando vazamento de memória em execuções repetidas.

Cache de compilação

const compileCache = new Map();
function getCompiled(text) {
  if (compileCache.has(text)) return compileCache.get(text);
  const c = math.parse(text).compile();
  compileCache.set(text, c);
  while (compileCache.size > 80) {
    compileCache.delete(compileCache.keys().next().value);
  }
  return c;
}

É um cache FIFO de tamanho fixo — nunca cresce além de 80 entradas.

Preservação da câmera 3D

Em Plotly 3D, re-renderizar enquanto o usuário arrasta a cena pode travar o controle de órbita. O programa adota três defesas:

  1. Lock de interação: eventos de mouse/touch no canvas 3D marcam interacting=true, e run() é adiado até o fim da interação.
  2. Captura de câmera: antes do react, a câmera atual é lida de gd._fullLayout.scene.camera e passada de volta.
  3. uirevision sensível à estrutura: o valor é "k-"+N+"-"+NS+"-"+bg. Mudanças estruturais resetam a câmera de forma limpa; mudanças só de corrente ou cor preservam a órbita.

11. Limitações e escolhas numéricas

11.1 Erro de discretização da curva

A integral de Biot–Savart é aproximada por uma soma de Riemann com regra do ponto médio. O erro é \(O(\Delta t^2)\). Aumentar \(N\) melhora a precisão, com custo linear em \(N_s\) por avaliação de \(\mathbf{B}\).

11.2 Regularização \(\varepsilon = 10^{-8}\)

Perto do fio, o denominador \((\|\mathbf{r} - \mathbf{m}_i\|^2 + 10^{-8})^{3/2}\) impede divisão por zero, mas distorce o campo quando \(\|\mathbf{r} - \mathbf{m}_i\|\) é menor que \(10^{-4}\). O parâmetro minD evita que a integração chegue tão perto.

11.3 Normalização \(\hat{\mathbf{B}}\)

A integração por comprimento de arco funciona bem onde \(\|\mathbf{B}\|\) não é nulo. Em pontos de equilíbrio, a direção é indefinida; o programa corta a linha quando \(\|\mathbf{B}\| < 10^{-14}\).

11.4 Critério de fechamento

A heurística "distância ao início menor que \(0.9h\)" pode falhar em campos com múltiplas escalas. Para linhas que não fecham, o programa corta em \(S_{\max}\) passos ou \(R_{\max}\).

11.5 Custo computacional

O programa impõe um orçamento que depende do perfil (3×10⁷, 6×10⁷ ou 2.4×10⁸ operações por execução). Se \(N_s \cdot S \cdot L\) excede esse valor, os steps são reduzidos automaticamente:

$$S \leftarrow \max\!\left(20,\; \left\lfloor S \cdot \sqrt{\frac{\text{orçamento}}{N_s \cdot S \cdot L}} \right\rfloor \right)$$

e o aviso "passos=\(S\)" aparece ao lado das estatísticas.

11.6 Física simplificada

  • \(\mu_0/(4\pi) = 1\) (unidades arbitrárias).
  • Corrente \(I(t)\) avaliada no parâmetro local de cada segmento (não no tempo global).
  • Fios infinitamente finos (sem raio físico).
  • Sem meios materiais (\(\mu_r = 1\)), sem campos elétricos variáveis.
  • Sem relatividade: correntes estacionárias ou quase-estacionárias.
Dentro dessas aproximações, o simulador resolve exatamente o problema de Biot–Savart com a precisão da discretização e do integrador escolhidos.
